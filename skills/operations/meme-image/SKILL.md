# 梗图制作

使用咩咩当前的人格、创意和用户偏好。制作要求根据这次的原图与意图确定。

## 在 Hermes 中做图

将成熟的创意、文字和画面要求交给已有制作程序。要改已有图片时给出原图路径；原创画面可以只提供完整构思。

```bash
"$HERMES_HOME/scripts/meme" image --input "/图片的路径" --line "这次要表达什么、改哪些字或画面、哪些细节保留"
"$HERMES_HOME/scripts/meme" image --line "完整的原创画面、人物动作、图上文字与位置"
```

命令返回成图路径。检查实际成图，然后在回复中用 `MEDIA:绝对图片路径` 交给飞书。用户继续修改时，把当前版本和这次要求再次交给同一个命令。制作说明留在工具调用里，正常回复呈现作品与简短说明。

## 素材和作品卡

同一个脚本还提供：`fetch` 抓新素材，`pool` 查看 A 的新闻线索与 B/C 的原帖和本地图片路径，`templates --line "关键词"` 找已有参考图，`status` 查看作品记录。

做日报时，`image` 加 `--record --premise "简短选题"` 将成品存入当天作品。可用 `--source-url` 记来源；使用 A 的线索时加 `--event-key`，完成后标记为已使用。`pick` 看图挑现成 AI 梗，`remake` 为这些图改中文。最后 `card` 通过咩咩发送已有九宫格作品卡。普通聊天直接用 `image` 并返回图片即可。

## 当程序请求判断现成 AI 梗图

打开完整图片，判断它是否在用梗、幽默或讽刺表达 AI 相关内容。模型、厂商、工具使用、人机关系都可以；普通 AI 资讯或教程配图不自动算梗图。

是 AI 梗图时返回 `{"about_ai":true,"what":"一句中文说清作品表达"}`，否则返回 `{"about_ai":false}`。此任务只作判断，不生成制作说明。

## 当程序请求“制作说明”

此时仅返回一个 JSON 对象，包含 `panels`、`lines`、`painting_prompt`。原图、任务类型和要求由本次输入提供。

- 改中文：理解原句的意思和语气，再用自然中文表达。保留说话人、关系和暗指，专名及水印按原样保留。
- 加字：使用给定文案，结合原图的留白、对话框和人物关系确定位置。
- 修改：按本次反馈调整。用户给出明确的新文案就照用；提出画面修改时，将该改动写进画图说明，保留其他有用的原图细节。

`panels` 按阅读顺序编号，每格包含 `no`、`position`、`content`。位置用整张、左、右、上、下、左上、右上、左下、右下，或“第 r 行第 c 列”。

`lines` 按阅读顺序列出每段文字，每条包含 `no`、`panel`、`where`、`original`、`zh`。`where` 使用格子上方、格子下方、对话框里、输入框里、人物身上或物体上。新增文字的 `original` 留空；保留原字的 `zh` 与 `original` 相同。

`painting_prompt` 以“这张图由 N 格组成，第 1 格在位置，第 2 格在位置。”开头。格数和位置按 `panels` 填写。逐处改字用“把第 N 格位置的‘原文’换成‘新文’”，实际引号使用中文双引号；新增文字用“在第 N 格位置写‘文字’”。保留原字的项目不写改字指令。要求改变的画面内容在同一段里具体说明。

制作说明以这句结尾：

> 文字放在指定位置，样式沿用原图。画面中未要求修改的内容、颜色、画风、清晰度、模糊和颗粒感保持原样。
