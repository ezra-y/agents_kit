# 数据表与 PostHog 看板

## 先确定统计方式

读取项目既有指标与事件定义，再核对样本。定义缺失时，在任务记录中明确选择，不沿用其他项目的事件名称、内部用户群组编号或观察天数。

| 项目 | 要明确的内容 |
| --- | --- |
| 到站人群 | 哪个域名和页面、哪些广告标记、首次到站时间范围、去重单位 |
| 广告归属 | 首次还是末次广告到站；同一人多次访问或跨广告访问怎样计算 |
| 后续观察 | 从哪次到站开始、观察多久、截至何时；未满观察窗口的访客怎样标注 |
| 事件 | 登录页、注册、创建密钥、调用、充值等概念对应的真实事件或页面 |
| 排除 | 仅使用项目已定义并能验证的内部测试人群和流量规则 |
| 身份 | 匿名访问与注册后的用户怎样关联，跨域是否仍能对应到同一人 |

### 日期与来源筛选

先根据到站日期和来源参数确定人群，再通过该人群的稳定身份读取后续事件。注册后进入其他域名或页面时，来源参数可能不再存在。

到站日期范围与后续观察窗口分别处理。例如选择某两天到站的人，仍可观察他们随后若干天的注册；界面说明与实际查询保持一致。

复用旧查询时，逐项检查写死的项目、主机、广告标记、日期下限、观察天数和排除群组。保留符合当前统计定义的查询，按当前工具支持的方式更新筛选。

## 广告汇总表

每行一条广告，保留广告编号与可读名称。广告数量来自当前批次。

- 平台字段：曝光次数、点击次数、点击率、点击费用、花费、币种、统计日期。
- 站内字段：去重到站、进入登录页、注册、项目实际激活步骤及首次使用人数。
- 比率注明分母。整体注册率使用整体注册人数除以整体到站人数，组间百分比不直接平均。
- 平台点击次数与站内访客人数分列，按各自统计定义解释差额。
- 同一人多广告归属时，先核对统计规则，再决定能否把分广告人数相加。

先核对原始行数、事件去重、汇总与明细，再查看百分比、长文本、时间和列宽的实际显示。

## 用户访问表

需要细查访问过程时，保留这几层：

| 工作表 | 内容 |
| --- | --- |
| 逐位访客 | 访客编号、广告归属、首次到站、实际到达步骤、简明路径 |
| 逐页明细 | 每次打开页面的序号、时间、地址、已记录点击、停留和下滑 |
| 原始事件 | 事件编号、访客／会话／窗口编号、原始时间、事件名和使用到的属性 |
| 注册用户完整路径 | 注册用户从广告到站至观察截止的页面与动作顺序 |

这些工作表可以合并到既有结构；只增加用户本次需要的内容。

**事件对应方法：** 按访客、会话、窗口和时间排序，匹配具体页面的打开与离开。路径相同的多次访问仍保留为多行。按钮点击只关联实际发生的那次跳转，返回登录页不会自动产生新的按钮点击。

**缺失数据：** 缺少离开或滚动记录时，显示“未记录”或“未知”；记录值为零时显示零。没有失败事件时，只能记录“未观察到成功调用”，无法判断有没有尝试调用。页面出现或停留时间本身不证明登录失效、机器人访问或用户离开原因。

保留原始事件时间，用项目约定的时区显示辅助时间。使用时区库转换，避免把某地固定时差复制到其他日期和地区。

## 看板制作

执行前通过当前 PostHog 连接器发现并读取看板、查询和转化统计技能。优先使用已验证的项目指标、现有图表与原生查询能力；只有实际计算需要自定义关联时才采用 SQL。

推荐排列：

1. 顶部：到站人数、注册人数、到站注册率。
2. 各广告对比：一行一条广告，保持广告名称一致。
3. 转化过程：按项目实际步骤展示，各广告独立图同时可见。
4. 注册后使用：创建密钥、首次使用、充值等已采集信息。
5. 平台投放数据：曝光、点击和花费，标明数据更新时间。

在相同时间窗口里“发生过某事件”的人数，与严格按顺序完成所有前序步骤的转化人数分开命名。使用转化图时确定步骤顺序、时间窗口和去重单位。

图表数量取决于当前广告数。各广告图可以两列排列，长表占整行，按实际文字与列数调整尺寸。

### 保存后的验证

- 全部广告：关键数字与同范围的数据表核对。
- 单条广告：选择有后续转化和无后续转化的实际广告（存在时），检查归属与后续事件是否保留。
- 日期：使用有实际访问的范围和无访问的范围，检查日期筛选是否生效。
- 独立图：逐条核对广告标记；相同来源定义下与对应汇总行一致。
- 显示：分母为零时保留空值或“无数据”；百分比按字段单位显示一次；检查保存后的排版。
- 平台导出卡片是固定数据时标明其覆盖日期，避免让日期筛选产生“也已重新统计平台费用”的误解。

数据、筛选与显示验证完成后保存链接。后续刷新时同时更新文件、Notion 统计日期和已变动的固定数据。
