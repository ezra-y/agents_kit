# 输入与交付

## 每批需要确定的信息

优先从任务、已有主页面、平台和已提供的会话取得信息。会改变广告选择、数据统计或文件共享范围的缺失信息，需要集中询问；不依赖该信息的部分继续执行。

| 信息 | 取得方式 |
| --- | --- |
| 品牌、产品、投放场景、批次日期 | 当前任务和已有广告系列 |
| 平台、广告账户、本批广告编号 | 广告后台或已核对的导出 |
| 实际素材、文案和落地链接 | 具体广告／发布帖子的实际版本 |
| 广告统计日期、时区、币种 | 平台报表设置 |
| PostHog 主机、项目、观察截止时间 | 已有看板、项目设置和任务要求 |
| 访客去重、广告归属、观察天数 | 既有指标定义或本次明确选择 |
| 事件和页面对应关系、测试用户排除方式 | 项目实际埋点与既有统计定义 |
| 正式 Notion 工作区、父页面、本地交付目录 | 用户指定位置或本项目既有正式入口 |
| 本次需要更新的文件和看板 | 读取既有内容后确定 |

沿用该项目的广告名称。新建归档名称需要统一时，可采用 `品牌-场景-日期`，广告组用 `需求-受众`；实际投放名称同时保留，方便回到后台查找。

## 本地目录

沿用既有目录；新建批次目录时按产物安排：

| 位置 | 内容 |
| --- | --- |
| `广告清单.csv` | 广告编号、名称、受众、实际素材、落地链接和来源会话 |
| `素材/` | 当前实际素材与明确标识的历史版本 |
| `导入包/` | 平台导入 CSV、引用素材和完整 ZIP |
| `页面/` | 落地页截图及截图日期、地址、尺寸 |
| `数据/` | 平台导出、行为明细、Excel 与统计定义 |
| `资料目录.md` | 正式 Notion、PostHog、文件和会话的可点击入口 |

只创建本次需要的目录。访问者明细保留在用户授权的工作区；通用技能和公开说明只保存方法与字段结构。

## Notion 页面

沿用用户已有栏目。新建时按查阅顺序安排：

1. **本批资料**：产品、场景、投放日期和广告清单。
2. **投放素材与落地页**：每条广告的图片、文案和链接，落地页存档。
3. **导入文件**：完整文件包与必要的导入说明。
4. **数据表**：简洁的逐广告汇总，完整 Excel 附件，统计时间。
5. **PostHog 看板**：可点击入口及数据更新时间。
6. **相关记录**：创作、投放、整理会话和本地目录。

主页面作为总入口，按文件数量和正文长度决定是否建立子页面。相同资料保留一个正式版本；其他页面提供链接。

## 更新已有批次

更新前读取广告清单、文件列表和目标页。比较广告编号、来源文件、统计时间和内容，只处理需要新增或更新的项。

广告清单增加成员时，逐项检查导入包、素材存档、数据汇总、已有访问明细、看板广告筛选和独立图的覆盖范围。数据文件也属于文件交付。沿用项目既有统计定义查询新增广告；确实没有事件时保留该广告并注明查询范围，无法访问数据时保留待完成状态。

每个既有产物需要有当前状态及依据。素材未变化可记录无需变更；数据表的广告行、看板的来源筛选和统计截止时间需要分别核对。用户要求优先处理的产物决定执行顺序，明确限定的交付范围决定执行哪些项。

平台指标与站内指标统计时间不同，可以各自保留日期。新批次沿用旧广告参数时，结合投放日期和编号区分；仅靠相同 `utm_content` 无法区分两次投放。

交付时给出正式入口，并简短列明本次新增、更新和待完成项。
