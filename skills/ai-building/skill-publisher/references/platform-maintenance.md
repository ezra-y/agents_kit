# 平台维护

本文件只在发布平台、官方命令或适配器需要核对和更新时读取。

## 事实源顺序

1. 平台官方规范或产品文档；
2. 本机当前官方 CLI 的 `--version` 和 `--help`；
3. 平台官方组织的源码仓库与 Release；
4. 登录后的官方控制台；
5. 社区实现，只用于理解设计。

冲突时停止会产生外部修改的动作。不要用搜索摘要、旧回执或社区教程替代官方
规则。

## 登记位置

平台能力和官方来源只维护在 `assets/platforms.json`。`SKILL.md` 只描述稳定流程，
不复制易变命令和网页字段。

每个平台至少登记：

- 稳定 ID 和显示名称；
- 适配器类型；
- 自动化边界；
- 官方发布入口；
- 官方规范或文档；
- CLI 探测命令；
- 用户能理解的计划动作；
- 审核型平台的正常交接说明。
- 公开页不在既有官方域名时，明确登记 `verification_hosts`。

URL 只能来自平台官方域名、官方 GitHub 组织或官方控制台。

## 更新步骤

1. 打开 `assets/platforms.json` 中全部官方来源。
2. 运行登记的 CLI 探测。
3. 对照当前适配器使用的命令、参数和返回字段。
4. 核对认证、版本、许可证、审核和公开验证方式。
5. 规则变化时只改对应适配器和平台登记。
6. 添加或更新单元测试夹具。
7. 运行全部测试。
8. 用真实平台做 read-only 或 dry-run。
9. 只有发生有意义的 Skill 更新时才做一次真实发布验收。
10. 更新 `last_reviewed_at`，记录实际核对日期。

`source_review_ttl_hours` 控制一次语义核对的有效期。它不是文档缓存时间，而是把
“我刚看过官方规则”限制在同一轮发布窗口内。

## 适配器边界

`github`

- 发布和查询都使用 GitHub 官方 CLI/API。
- 同版本 tag 指向其他提交时返回 `version_conflict`。

`clawhub`

- 发布、指纹比较和查询使用官方 ClawHub CLI。
- 发布许可证和扫描状态每次重新核对。

`github_import`

- 适用于从公开 GitHub 仓库导入的平台。
- 没有稳定 API 时只返回官方入口，不保存网页选择器。

`auto_index`

- 适用于由安装遥测或爬取驱动的索引。
- 状态叫 `indexed`，不叫 `published`。

`reviewed_form`

- 适用于登录、授权和人工审核平台。
- 自动准备与验证，表单返回 `manual_handoff`。
- 用 `record` 保存提交事实；只有已登记官方域名上的公开页才能自动变成 `verified`。

## 新增平台条件

满足以下条件再进入核心平台：

- 有持续可访问的官方入口；
- 可以验证公开结果或审核状态；
- 有真实用户需求；
- 维护价值高于账号、OAuth 和页面变化成本；
- 不要求把长期凭据保存进 Skill。

只为增加平台数量、但无法可靠验收的目录不进入默认配置。
