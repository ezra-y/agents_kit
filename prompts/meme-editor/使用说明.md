# 咩咩主编文稿

这套文稿保存在 agents_kit 的私人提示词库中，用于审阅和接入。没有安装到任何客户端，没有修改 NAS 或启用 W5。

| 文件 | 用途 | Hermes 中的位置 |
|---|---|---|
| `SOUL.md` | 咩咩是谁、怎样观察、怎样表达 | 咩咩独立实例的 `HERMES_HOME/SOUL.md` |
| `AGENTS.md` | 工作目标、ABC 三路素材、制作与修改方法 | 咩咩的工作目录，作为项目说明加载 |
| `memories/USER.md` | Ezra 已明确表达的偏好，初始稿 | 咩咩实例的 `HERMES_HOME/memories/USER.md`；接入时合并已有内容 |
| `references/cases.md` 与 `assets/` | 三个有原图的表达参考 | 咩咩工作目录内，需要时按 AGENTS.md 指引读取和看图 |

SOUL 和项目说明的分工已经按 [Hermes 人格文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/personality)核对。人格从实例目录读取，放在普通工作目录并不会自动作为人格加载。项目中如已有优先级更高的 `.hermes.md` 等文件，需要把工作说明纳入实际加载的那份文件，避免增加一个从未被读取的文件。

USER 初稿只包含已经表达过的偏好。没有创建预填的 MEMORY 文件；之后由智能体用记忆工具记录真正学到的经验。Hermes 的用户偏好与经验记忆位于 `memories/`，通常在新会话开始时作为快照加载。修改人格和记忆后，应在新会话中验证内容实际生效。[Hermes 文件分工](https://hermes-agent.nousresearch.com/docs/user-guide/which-file-does-what)，[持久记忆](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)

创作、找图、中文化的具体工具调用可以继续通过现有技能提供。Hermes 的技能按需读取，适合放操作步骤、输入输出和某个制作工具的说明。[Hermes 技能机制](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)

这次没有新增一个汇总所有工具的大技能。现有 `meme-make` 等技能与程序拼接文字中，还有“20 条候选、先找落差、预先给三张模板”等旧要求。接入这套工作方法时，需要一起调整这些实际调用要求，保留模型返回格式与制作工具所需的参数。否则新的人格仍会受到旧流程的限制。

当前本地 W5 通过 `services/meme/prompts.mjs` 把 SOUL 和选中的技能拼接后，直接调用模型。它没有启动独立的 Hermes 咩咩实例，也没有自动加载这里的 USER、AGENTS 或案例。运行中的小黑是另一角色。本轮 NAS 连接超时，未重新验证那边是否已有后续部署变化。

接入时有两个实际选择。

- 保留现有 W5 模型调用，显式加载工作说明和用户偏好，并传入真正需要看的图片。改动较少；持久反馈需要程序另行读取和更新。
- 让咩咩作为独立 Hermes 实例工作，使用自己的记忆、会话与技能，继续调用已有采集和制作能力。它能在任务中主动补看资料、使用工具和记忆，但需要调整 W5 的调用方式，任务耗时和调用次数也会更不固定。

本次完成的是可审阅的人格与工作文稿，尚未进行上述接入或模型试跑。案例展示表达空间，不能视为这套提示词已经产出过同等质量的证明。
