# `.local/`：Skill 内的本机私有区

这个目录就在 **Skill 根目录内部**。

除本说明文件外，整个 `.local/` 都被根 `.gitignore` 忽略。

程序第一次运行时创建：

```text
.local/
├── db/
│   ├── knowledge.sqlite     # 官网字段观察、映射证据、locator 统计、候选
│   ├── private.sqlite       # 用户答案、履历记录、材料索引
│   └── runtime.sqlite       # 任务、状态、动作日志、恢复点、提交保护
├── materials/
│   ├── resumes/
│   ├── portfolios/
│   ├── transcripts/
│   ├── photos/
│   └── other/
├── browser-profile/         # 秋招专用浏览器登录状态
├── runs/                    # 每次运行的快照、截图索引和调试记录
├── learning/                # 尚未审核的字段、映射、配方和知识提案
├── evidence/
│   └── sites/<域名>/        # 按站点隔离的证据索引和新执行证据
├── fixtures-raw/            # 未脱敏页面与网络样本，绝不提交
├── backups/                 # 本地备份
├── secrets/                 # 仅在确有需要时保存的本机秘密
└── tmp/                     # 普通临时文件；被 evidence 索引引用的旧脚本不得删除
```

## Git 与 clone

- `git clone` 只得到代码、公共知识、脱敏夹具和本文件。
- clone 后第一次运行 `applyctl init`，才创建其余 `.local/` 子目录和数据库。
- `git pull` 一般不会删除 `.local/`。
- 删除整个仓库、重新 clone、`git clean -fdx` 或 `git clean -fdX` 可能删除 `.local/`。
- 执行危险操作前，先运行 `applyctl local backup`。

## 三道保护

1. 根 `.gitignore` 忽略 `.local/*`。
2. `checkGitBoundary()` 检查暂存区、已跟踪文件和数据库位置。
3. 提交前钩子运行 `applyctl doctor --git-boundary`。

注意：`git add -f` 可以绕过 `.gitignore`，所以第二道检查不能省。

## 私有答案表示“意思”，不保证和网站选项一字不差

`profiles/` 和私有数据库里保存的是用户事实、偏好、可接受范围和优先级。
它们不是某个招聘网站的固定选项原文。

例如：

- `["北京", "广州", "上海"]` 表示按这个顺序优先，不表示网站一定提供相同文字。
- “产品”表示职位方向。网站写“产品类”时，可以选择“产品类”。
- “线上、线下都可以，线上优先”表示可接受范围和首选项。
- “AI 或互联网”表示行业含义。网站只有“互联网/电子商务”时，可以选择该项。

填写时必须先读取当前网站的真实选项，再按语义、范围和优先级选择最接近的值。
不要要求用户照抄网站选项。不要因为文字不同就反复追问。

“按语义填写”不表示可以跨栏目挪内容：

- 教育、工作、项目和奖项必须保留原记录类型。
- 项目缺日期或角色时先从原简历、本地仓库和已有证据补全；找不到就记录缺失，
  不得丢掉项目或塞进“作品链接”。
- 官网没有奖项栏目时，奖项保留在附件简历，不塞进作品链接、自我描述或项目描述。
- 作品链接只写真实 URL。
- 修改同一条履历的日期仍是更新原记录，不应生成一条重复履历。

只有以下情况才询问用户：

- 网站选项和已保存意思发生明显冲突。
- 有两个差异很大的选项都可能正确。
- 选择会产生用户没有表达过的重要承诺。

如果资料确实为空，先集中收集一次，再继续填写。不要每遇到一个字段就单独问一次。
