# 官网投递规则

投递名额属于招聘规则，通常不在 JD 中。先核对规则对应的公司、招聘项目、届别和渠道；同一家公司不同项目可能有不同名额。

## 查询流程

1. 采集岗位时一并查看本届常见问题、投递须知、招聘公告及岗位详情，展开相关问答。复用已取得的页面与响应，从中提取完整规则；只为尚缺的信息增加请求，保留官网原文、准确链接和核实时间。
2. 页面未显示数量时，观察官网正常加载的只读请求，读取当前岗位适用的数量规则。站点配置中未使用的默认页面、预览示例和旧届别问答只能帮助查找入口。
3. 接口依赖账号时，交给 recruitment-session 复用已有状态，以当前账号或受保护接口确认登录，再在同一次会话读取尚缺的上限、剩余额度和已有申请。登录已确认而数据读取失败时，继续检查对应请求和页面入口，并记录技术原因；只有官网确认需要验证账号时才请求用户完成登录。查询规则不提交或撤回申请。
4. 按下表记录结果。数值、时间窗口和项目范围一起展示；不同项目的名额分别写明，跨项目共享关系未经确认时不计算公司合计。

| 查询结果 | 展示与处理 |
| --- | --- |
| 已核实限制 | 显示上限及适用项目、时间范围、志愿顺序，附官网来源 |
| 当前入口未配置数量限制 | 明确写当前入口及渠道的系统查询结果；继续保留已查的公告依据 |
| 公开规则已核实，账号信息待验证 | 保留已知上限和适用范围，只将剩余额度或已有投递标为待验证 |
| 官网确认需要登录 | 写明待登录读取的具体字段，保留其它已核实信息 |
| 当前已登录，字段仍未取得 | 保存失败请求或已查页面、实际原因和下一步，将受影响字段标为待核实 |
| 官网未公布 | 说明已经检查的官网入口和字段，保留原始空值，避免猜测数值 |

## 已验证的招聘平台入口

### Moka

在当前岗位页面观察这两个只读请求，参数取实际页面和岗位：

- `POST /api/outer/ats-apply/website/applicant-limit-check`，参数为 `orgId / siteId / jobHireMode`。结果中的 `isSetting / total / duration / remainder` 表示通用规则是否启用、数量上限、月数和剩余次数。
- `POST /api/outer/ats-apply/website/job`，参数包含 `orgId / siteId / jobId`。读取该岗位的 `projectFolder.settings.deliveryLimit`。

当项目规则启用并包含当前 `campus` 渠道时，官网前端优先用项目规则显示上限和申请状态；在适用时间之外会显示项目暂未开放并禁用申请。保留项目名称、`content.limit`、起止日期及原始通用规则，逐个检查本批岗位所属项目。

`content.type=1` 表示未限定日期区间，数量仍由 `content.limit` 决定。`remainder=-1` 时，本次响应没有提供可用的剩余数字；已验证登录时也可能出现。登录状态由当前账号证据确认，剩余次数结合适用规则和投递记录核实。通用 `isSetting=false` 时仍需查项目规则；两者都未启用才能报告当前入口未设置数量上限。

部分响应由官网客户端解码。复用已加载页面的现有请求客户端，或由对应 PageScript 处理；客户端模块位置从本次实际脚本确认，不把打包模块编号当成稳定接口。

### 北森

读取当前岗位实际使用的 `GET /api/JobAd/GetJobAdInfo` 请求。`Data.SubmissionLimit` 中的 `IsCountLimit / MaxCount / CanCount / RecruitRuleName` 分别对应是否限制、总上限、当前剩余次数和规则名称。只有数量限制启用时才使用上限和剩余数值；限制关闭时记录当前入口未开启数量限制。另核对重复投递相关字段。

未登录时 `SubmissionLimit` 可能为 `null`，这时转到登录验证，不能由空值推断额度。`BSGlobal.Pages` 可帮助定位官网问答，但其中可能包含未使用的默认模板；沿当前导航进入对应页面，核对真实展示的招聘项目和届别。

### 飞书招聘及自建门户

同时检查招聘站首页与企业品牌招聘官网。飞书招聘页的 `#js-websiteInfo` 中，`website_info.web_visual_ui_config` 可能保存问答正文；用 JSON 和 HTML 解析器读取，并回到实际页面确认其项目与届别。`/api/v1/common/setting` 是基础字典，不代表投递规则。

公开问答仍不能确定时，登录后观察岗位申请前的只读检查与投递记录。只复用本次观察到的请求，不用最终申请动作试探上限。

## 保存和继续

公司保存 `limitStatus / limitText / limitSourceUrl / limitCheckedAt`。`maxApplications` 只在本批岗位适用一个确定上限时填写；存在多个独立项目时保留各项目规则。岗位可用自己的 `limitText / maxApplications` 表达具体适用规则。

状态使用 `verified`、`not_configured`、`login_required`、`unresolved`。`limitSource` 保留原文或原始接口字段，完整响应留在私有证据目录。

文档与原表展示同一份规则。用户选中岗位后，按该岗位的项目、时间窗口和当前账号剩余额度再次核对，再继续已有提交流程。
