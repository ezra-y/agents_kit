# 文档选择与自动处理

## 每次检查

1. 读取批次保存的文档、表格及材料位置，核对已有 taskId 的真实状态并更新批次；上次中断的运行按 get_status 恢复。fetch 当前完整文档并运行 `choices`。确认行缺失、关联变化或岗位材料变化时，只暂停受影响岗位；保留明确的检查结果供用户处理。
2. 按返回结果更新原表中的确认投递、已选数量及状态，读回验证。AI 不操作云文档确认项；原表中的手动勾选不触发这条文档流程。
3. 逐项核对 `ready` 对应任务的真实状态。已有已提交记录直接同步结果；提交结果不确定时核实原申请。其余选中岗位带准确官网链接、原表行身份和公司 `loginProfileName` 交给 job-application-submit。已有运行沿用原 `runId`；新运行将该档案传给 `apply.open_task` 的 `profileName`，随后按 recruitment-session 检查当前账号，再继续填写或提交。
4. 官网限制多志愿数量时遵守实际名额；超过上限时展示该公司的已选数量和可投数量，等待用户调整。顺序使用文档已展示规则。未知名额在进入官网后核实并更新。
5. 完成后局部更新文档中的状态和公司数量，保留用户确认块；同步同一岗位的表格记录。材料或申请内容变化时展示新内容并取得新的用户确认。

用户在本批已展示的材料和顺序规则下确认具体岗位，构成该岗位的明确授权。实际填写、独立审查与一次性批准令牌继续沿用提交技能；云文档只替换用户表达选择的位置。

## 定时任务

用户明确要求定时检查时，优先使用宿主提供的定时任务工具。先查当前会话的已有任务，复用相同批次任务，避免重复创建。Codex 使用 `automation_update` 的 heartbeat（当前会话定时检查），默认每 5 分钟检查一次。其他宿主用其已经配置的定时能力；不可用时如实说明需要用户发起继续。

保存的任务提示包含实际插件位置、dataRoot、批次绝对路径、文档 URL 和表格位置，要求先读本 Skill，再按“每次检查”执行。只处理该批由用户确认的岗位，沿用已展示材料。无变化、无可执行事项时保持安静；有真实提交结果、失败或需要用户处理的事项时通知。不得用通知代替执行。

工具确认创建成功后，将返回的任务编号保存在批次 `automationId`。用户停止自动处理时用原工具停用同一任务。任务完成后关闭本轮浏览器和临时运行；监控期间只保留宿主定时任务，不自建常驻轮询程序。
