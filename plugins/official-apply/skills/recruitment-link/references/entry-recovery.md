# 入口与页面恢复

输入是原公司/岗位范围、taskId/runId（如有）、原表行和当前失败。先保留已保存内容及现有证据；本流程输出可继续的入口/动作，或尚未解决的具体问题。

## 1. 根据实际页面分流

用当前浏览器工具读取最终 URL、页面截图/可见文字和导航结果。只在它们不足以区分原因时，再查加载错误、iframe 和本次页面请求；没有创建成功的 runId 时使用宿主现有浏览器诊断工具，不对不存在的运行调用 MCP。

| 观察结果 | 下一步 | 本次能得出的结论 |
| --- | --- | --- |
| 浏览器启动失败、DNS/连接超时、工具拒绝访问 | 环境故障交能力演进；工具拒绝按其实际要求处理 | 当前访问失败，网站内容尚未核实 |
| 当前链接显示下线/不存在，或跳到无关页面 | 按第 2 节查找企业当前招聘入口 | 当前链接失效；结论只适用于这个页面 |
| 截图有表单/导航，但扫描结果为空或缺动作 | 按第 3 节检查可见页面 | 页面已打开，扫描或操作尚未适配 |
| 当前页面要求登录或验证码 | 回 recruitment-session 第 2 节 | 需要完成登录步骤 |
| 当前官网明确说明某岗位停止招聘 | 记录该岗位官网原文和检查时间；按原授权处理其他记录 | 该岗位停止招聘，不扩大到公司经营状态 |

## 2. 查找并恢复当前入口

1. 从已确认的企业官网首页进入“加入我们/招聘”。旧站提供迁移链接时先核实该链接。官网导航仍找不到时，用当前搜索工具查询公司名称与招聘类型，打开实际结果核实企业归属；沿用 [搜索工具选择](find-sources.md)，搜索摘要仅作线索。
2. 企业官方导航所指向的招聘平台可以作为入口依据。保留发现路径、当前 URL 和页面证据；仅名称相同的第三方列表不足以确认。公司简历入口与具体岗位分别核实，岗位更换继续遵守原选择授权。
3. 找到入口后按 [表格回写](table-setup.md) 在原行更新来源链接和检查结果，保留旧链接与证据于原批次记录。先查原任务是否已有运行/提交历史：未运行任务可用原 source/externalRowId 和完整绑定重新导入；有历史时程序锁定身份，不原地改 URL。已有提交或结果不确定先核对官网记录；其他情况为替代入口创建新 externalRowId 的任务，在原批次绑定中记录旧/新 taskId 与同一个原表行，后续清单只继续替代任务。
4. 用 [任务导入](../SKILL.md#43-导入并保留原行身份) 的 task import 检查并导入，读回实际任务 URL 和材料绑定，再交 recruitment-session 建立会话、检查真实登录。旧 run、旧账号状态和提交批准不转作新入口的成功依据；旧会话证据保存后按原流程关闭。
5. 官网导航和搜索均未找到可确认入口时，记录“当前入口未找到”、已查范围和下一步。需要技术诊断的失败交能力演进后再决定阻塞；访问失败与企业经营状态分别报告。

## 3. 页面可见时恢复操作

1. 用当前浏览器截图核实正在显示的页面，查看是否仍加载、位于 iframe、折叠栏目或自定义控件。用真实控件定位或 Computer Use 完成当前步骤，按 [视觉操作](../../resume-fill-review/references/evidence-recovery.md#视觉操作) 流程读回；不等待一个网页上本来就不存在的“下一步”。
2. 需要确认入口、字段或保存行为时，用同一浏览器的网络观察工具，记录一次当前授权操作产生的请求方法、URL、响应状态及必要结构。只读查找不点击保存/投递；已有填写授权时可观察草稿保存，并重新打开确认。参数来自实际请求，不猜接口路径；Cookie、验证码和原始响应留在私有目录。
3. 已看清操作但现有脚本仍不适配，将具体控件/请求证据交 [能力演进](../../recruitment-capability-evolution/SKILL.md)；普通页面无需额外安装逆向工具。修复后回原步骤验证，原字段和保存状态继续沿用。

## 4. 恢复记录与下一次执行

复用现有批次绑定和问题记录，每项保留“已完成步骤、当前证据、已尝试方式及结果、下一步或重试条件”。恢复时先读这项记录：条件未变就执行尚未尝试的路径或继续下一家公司；登录、链接、工具或修复发生变化后，再验证对应失败步骤。完成修复后更新同一条记录，不重复生成阻塞清单。
