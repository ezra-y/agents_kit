# recruitment-link

招聘信息保存在插件外。插件提供流程、空表模板和位置管理工具，不附送几千条招聘记录。
命令在插件根目录执行。先解析配置中的私有数据绝对目录，下文 `<dataRoot>` 用这个真实值替换。

已有公司任务仅需修复入口时，直接进入第 4.2 节，沿用原表和公司范围。

## 1. 找到已有的表格与来源

### 1.1 读取专门的位置记录

执行 `python3 skills/recruitment-link/scripts/table-locations.py --data-root <dataRoot> show`。
读取固定位置 `<dataRoot>/tables/locations.json`，返回已登记的 sources（招聘来源表）、candidates（具体岗位表）。位置既可以是文件，也可以是链接。
已有任务时也读位置记录，后续结果仍要写回对应表；不只在第一次导入时读取。

### 1.2 复用或登记

用户本次指定的来源优先；切换默认工作表需要用户明确意图。按 [表格位置与创建](references/table-setup.md) 检查文件或链接可访问、读取实际列，再登记。
找不到文件或链接无权限时，说明哪一个位置不可用，保留原登记；不能把访问失败当成“没有表格”而另建一张。
未登记时一次询问：“有现成的招聘表或数据文件/链接吗？如果没有，你希望用本地表格还是飞书多维表格？”已有回答直接复用。

## 2. 没有表格就创建

### 2.1 按用户选择执行

本地选择按 table-setup 的 create-local 命令生成空 CSV；飞书选择按同文档的 base-create/table-create 命令及模板建表。
先有招聘来源表即可开始；需要保存具体候选岗位时再复用或创建 candidates 表，不要求用户先建完两张。
创建成功后立即登记真实路径或链接、表格编号和列映射，再读回确认。已有表复用，不覆盖原内容或用户选择。

### 2.2 表格已有，来源还没有

创建空表不等于已经有招聘数据。用户也没有来源时进入第 3 步，不能继续反复索要不存在的招聘表。
用户明确选飞书但当前没有可用连接时，按该工具的认证流程处理；可先保存本地搜索结果，说明尚未写入飞书，不擅自替用户改偏好。

## 3. 获取一批实际可用的招聘来源

### 3.1 复用外部数据

已有本地数据库、CSV、JSON 或外部数据链接时，按 [来源细节](references/source-routing.md) 读取，保留原来源和更新时间。
只读取用户指定的范围，数据仓库更新与插件升级分开。公司列表、招聘公告和具体岗位分别标记，不把记录数说成已核实岗位数。

### 3.2 用户没有来源

按 [没有来源时搜索](references/find-sources.md) 先复用意向和条件，再用当前可用的搜索与网页工具收集一小批，核对官网后写到招聘来源表。
初始默认展示最多 10 条，优先给用户可检查的结果；不足时如实报告。用户确定方向或要求更多后再继续。
筛选条件不足就集中问必要信息，不按用户没给的行业、城市或届别替他排除。只读搜索与建表不等于允许填写或提交。

## 4. 从表格生成本批任务

### 4.1 确定处理范围

继续填写前，按 [表格筛选与收尾](references/fill-selection.md) 从当前表格生成清单：已勾完成、已保存、已投递或提交结果不确定的行排除，只补允许行中的空白内容。普通处理范围与最终提交授权仍分开。
验证企业官网 URL，区分公司简历入口与明确岗位。官网没有独立简历入口且缺少明确岗位时记录原因；不为进入表单擅自决定岗位。
缺少来源链接时通过官网导航、页面源码或真实请求查找；需要允许新招聘域名时依已有授权调用 `apply.approve_host`。

### 4.2 恢复失效入口

原链接无法访问、页面提示关停或跳到无关页面时，按 [入口与页面恢复](references/entry-recovery.md) 确认实际问题；属于旧入口失效时从企业官网寻找当前入口，核实后回到原登录/填写阶段。保留原表行、旧链接及核实依据；此路径不启动新一批公司搜索，也不重新索要已有资料。

### 4.3 导入并保留原行身份

按 source-routing 中的输入字段生成本批 JSON，先运行 `node bin/applyctl.js task import --file <queue.json> --dry-run --json`，再去掉 dry-run 导入。
同批共用 batchId；简历附件和结构化履历都绑定。状态和结果由程序维护，不把备注当作禁止提交的控制。
原行身份写进 externalRowId；后续按 table-setup 的回写步骤更新该行，不靠公司名猜行。

## 5. 交接与结果写回

用户只要求整理来源时，在表格读回确认后结束；用户还要登录或填写时交给 recruitment-session。
交接 `taskId`、`batchId`、官网 URL、原表位置、原行身份和本次目的；填写者继续读取同一个位置登记文件。
填写、独审、阻塞或提交产生结果后，按 [表格位置与创建](references/table-setup.md) 第 5 节更新原行，并读回具体字段。
当前由活跃 Agent 调用文件或飞书工具读写；没有后台自动同步或表格勾选监听。
