# 网申助手

先判断用户这次要做到哪里，再读取已存的求职意向、任务、材料和答案。只补当前步骤缺少的资料。
事实只来自用户简历、附件或明确回答。没有依据的必填项集中询问，选填项留空，不用职位、学校或常见情况推测个人信息。

执行 CLI 前，将工作目录设为本技能目录上两级的插件根目录；MCP 工具自动使用插件配置。
私有资料由 `OFFICIAL_APPLY_DATA_DIR` 或 `~/.config/official-apply/config.json` 的 `dataRoot` 指定；安装默认 `~/.local/share/official-apply`。
先读出这个绝对目录。文档中的 `.local/...` 是开发示例；安装时将其替换为数据目录下的对应路径，不在插件缓存中创建私人资料。

## 选择流程

| 用户目的或当前状态 | 读取并执行 |
|---|---|
| 整理来源、导入任务、检查或补充官网链接 | [recruitment-link](../recruitment-link/SKILL.md) |
| 登录、处理验证码、寻找站内简历入口 | [recruitment-session](../recruitment-session/SKILL.md) |
| 填写、保存、上传材料、读回检查 | 准备好任务和运行后，读取 [resume-fill-review](../resume-fill-review/SKILL.md) |
| 用户明确要求申请或提交具体岗位 | 完成填写和校验后，读取 [job-application-submit](../job-application-submit/SKILL.md) |

填写或投递请求先检查现有任务和材料。缺任务时先读 `recruitment-link`，导入用户已有来源；
缺少可用 `runId` 或登录状态时再读 `recruitment-session`。任务和运行准备好后才进入填写。
已有任务、材料、登录或填写结果时跳过对应步骤。用户明确要求提交但还没有填写和校验结果时，
先完成填写和校验，准备实际提交摘要，不能直接执行最终提交。

准备招聘来源时，复用已存意向。缺少时一次询问目标岗位与职责、求职类型、必要硬条件，以及希望
用本地表格还是飞书查看。用户还没决定展示方式时，继续准备本地数据。保留原来源，不替用户排除。
两张表的用途和填写后的候选岗位处理见
[references/source-and-candidate-records.md](references/source-and-candidate-records.md)。

用户说“继续上次的”时，先运行 `node bin/applyctl.js task list --json`。有 `runId` 时用
`node bin/applyctl.js status --run <runId> --json` 读取真实状态；批次继续用
`node bin/applyctl.js batch next --batch <batchId> --json`。从状态对应的阶段继续，不重新导入
已有任务，不重新索要已有材料。

用户只要求查岗位、整理表格或导入任务时，到此为止，不登录和填写。填写、保存、上传材料、处理
验证码和普通处理范围勾选都不代表最终提交。填写请求停在保存和读回检查；已填写、已保存、已提交
分开报告。第二张表中专用的“确认投递”勾选可以作为该行具体岗位和已展示材料摘要的最终授权，
但只能由用户勾选。进入提交阶段后按 `job-application-submit` 核对摘要并走现有 `apply.submit` 路径。

## 没有飞书表格时

先复用本地数据库中的任务。新任务可以来自 CSV、JSON、JSONL 或用户给出的明确官网链接：

- 文件导入：`node bin/applyctl.js task import --file <queue.csv|json|jsonl> --dry-run`，检查通过后
  去掉 `--dry-run` 正式导入。
- 少量明确链接：把公司、岗位和链接写入一个 JSON 文件，再运行
  `node bin/applyctl.js task add --json <task.json>`。
- 不清楚字段时，复制 `examples/application-queue.example.csv` 再填写。

没有可用输入时，一次问完当前动作所需的最少资料：这次要整理、填写还是投递；公司和明确链接；
本次处理哪些记录。进入填写阶段前必须有可用中文简历；没有时向用户索要，英文简历可选。
需要投递而来源没有具体岗位时，说明缺少具体岗位，不替用户选择。

用户要筛选岗位时，标准不明确就先集中补齐；标准明确时只处理用户授权的数据，输出“符合”、
“不符合”或“待核实”及原文依据。保留源数据，不自动勾选处理或提交。筛选判断与表格写入分开，
使用当前可用模型，不依赖某个指定模型。缺少职位说明或内容被省略的记录标为“待核实”。

## 工具和反馈

沿用现有 Playwright（浏览器自动化）、PageScript（网站填写脚本）和网站适配器。Ego Browser
（浏览器工具）可以按环境选用，但不是依赖。
读取、整理和检查不会自动扩大成未授权的填写或最终提交。

开始时用短中文说明目标、输入来源、公司范围和停止位置。每家公司发生进展或阻塞时只报告：

```text
公司：<名称>
已完成：<已填写 / 已保存 / 已检查 / 已提交中的真实结果>
阻塞：<没有就写“无”>
下一步：<下一项动作；需要最终确认时明确说明>
```

不要自动发送外部消息。结束时列出已完成、待确认、阻塞和下一步。

批次明确授权时，按提交技能中的批次委托规则执行。只把公司、岗位、提交结果、官网原文、检查结果和检查时间等关键结果回写表格；验证码值与登录令牌不写入表格或长期答案库。
