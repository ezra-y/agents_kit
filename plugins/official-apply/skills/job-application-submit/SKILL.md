# job-application-submit

使用已经完成简历审查的 `taskId` 和活跃 `runId` 处理岗位申请。

## 流程

1. 确认岗位链接、岗位选择依据、登录态和服务器简历仍有效。
2. 填写岗位专属字段，选择意向城市、推荐方式和网站要求的声明。
3. 运行页面校验，停在最终提交按钮前。按 `resume-fill-review` 第 5 步完成该岗位的独立审查；岗位专属字段、材料或简历变化后重新采证复审。独审报告必须对应当前内容，未通过不进入最终提交。
4. 调用 `apply.submit { runId }` 做提交前检查，取得一次性批准令牌和批准摘要。
5. 向用户展示公司、岗位、城市、材料和可能产生的志愿顺序。
6. 用户在后续消息确认摘要，或第二张表中同一岗位的专用“确认投递”已由用户勾选且已展示摘要
   与当前批准摘要一致，或已有明确的来源范围、选择规则和材料批次委托时，调用
   `apply.submit { runId, confirm: true, approvalToken }`。
7. 从成功页、提交接口和应聘记录读取结果，按任务保存证据。
8. 结果不确定时，请用户在官网应聘记录中核对。核对后调用
   `apply.resolve_submission { runId, result, confirmedBy }`。这个工具只改本地结果，不再次点击。

聊天确认无需固定句式。表格确认必须来自专用“确认投递”字段，AI 不得代勾；普通范围、验证码和
状态复选框不能替代它。表格摘要不一致或当前环境不能读取该行时，展示当前摘要并等待后续确认。

## 岗位前置条件

- 明确岗位必须来自用户提供的岗位名称或链接，或者来自用户明确要求 Agent 代选岗位的结果。
- 公司招聘首页、职位列表、“校园招聘”或“社会招聘”不构成岗位选择依据。
- 用户要求批量处理或批量投递时，不自动获得决定具体岗位的权限。
- 缺少明确岗位时停止本公司的投递阶段，保留已填写的站内简历并记录原因；不能搜索职位后
  自行挑选一个继续。

## 程序边界

- 最终提交必须经过 `apply.submit`，不能用临时 Playwright 脚本直接点击。
- `confirm=true` 没有提交前检查签发的 `approvalToken` 时，工具会拒绝。
- `apply.submit` 本身不读取表格。Agent 读取“确认投递”并核对摘要后才能调用；当前没有表格监听器，
  因此勾选不会在后台自动触发。
- 令牌绑定任务、岗位页面和当前填写值；内容变化、过期或重新预检后失效。
- 每个令牌只能消费一次。提交结果不确定时不重试。
- 提交页出现验证码时先处理验证码并重新校验；旧的批准令牌不再使用。
- 批量申请可以集中展示一次摘要，但摘要必须逐条列出确定的岗位、城市和材料。替换任何岗位
  后重新检查并确认。
- 修改志愿顺序、撤回申请和补交材料属于新的外部操作，不复用提交批准。

## MCP

- `apply.inspect_page`：扫描岗位申请页的字段、按钮和当前状态。
- `apply.resolve_page`：准备岗位专属字段需要的答案。
- `apply.fill_page`：填写岗位申请页，但不执行最终提交。
- `apply.validate_page`：检查页面报错、缺失字段和实际填写值。
- `apply.advance`：执行开始申请、保存或换页，不点击最终提交。
- `apply.submit`：先生成提交摘要和一次性令牌，确认后只提交一次。
- `apply.resolve_submission`：用户核对官网后，把不确定结果确认为已提交或未提交。
- `apply.get_status`：读取任务状态、提交结果和阻断原因。
- `apply.close_run`：完成结果读取后关闭指定浏览器会话。

## 输出

```text
taskId
companyName
jobTitle
selectedCity
submissionStatus
applicationIdRedacted
serverReadback
evidencePath
```

读取并保存本岗位结果后，把控制权交回 `official-apply`。主入口可以继续同一批次中其他已由用户
确认的岗位；本 Skill 不自行扩大批次或决定下一条岗位。

需要理解批准令牌、页面变化和批量确认时，读取
[references/confirmation-guard.md](references/confirmation-guard.md)。
