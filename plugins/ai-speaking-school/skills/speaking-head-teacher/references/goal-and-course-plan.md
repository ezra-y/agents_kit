# 目标与课程计划：狗蛋执行指南

<!-- source: S1_班主任_狗蛋/02_目标与课程计划.md -->

## 使用方式

在 `onboard`、`create_plan` 或 `revise_plan` 时读取。把用户真实目标转成阶段路线，并让计划与教材同步生长。不要把这份文档当作背景综述；按其中判断直接产出或修改课程计划。

## 1. 从用户目标开始

目标通常由用户在入学对话中给出。大模型的工作不是替用户选择人生目标，而是：

```text
听懂用户真正想做什么
-> 澄清模糊、冲突或不现实之处
-> 找到最近会发生的真实场景
-> 把目标拆成可教学的路线
-> 与用户确认首个阶段
```

“提高口语”“变流利”“工作中能说英语”还不能直接排课。继续问到能够回答：

- 在哪里使用；
- 和谁说；
- 想完成什么；
- 有什么现成材料。

文本访谈只确认目标和自述，不能冒充实时口语测评。首节课再用真实任务观察起点。

## 2. 目标不只一种写法

目标只要能指导计划、教材和评估即可，不强制套句式。如果需要更完整的常用框架，可以检查：

```text
场景与对象
沟通目的和现实结果
需要理解、表达和互动什么
允许什么支援
完成证据
期限与投入
```

这是检查表，不是必填模板。简单目标不必写成长句；复杂目标可以分段表达。

## 3. 计划与教材并行

计划和教材互相约束：

```text
目标提出任务
-> 计划给出顺序
-> 教材检索发现可用章节和缺口
-> 计划按真实材料与用户时间修订
-> 教材按计划补齐
```

典型情况：

| 情况 | 处理 |
|---|---|
| 有成熟教材且高度匹配 | 用其章节骨架，调整顺序和取舍 |
| 教材只覆盖部分目标 | 保留可用章节，补定制章节 |
| 有 726 句等原始句库 | 重新组织成任务章节，不沿用句子顺序 |
| 完全没教材 | 先完成首阶段教材，再逐步扩建 |
| 用户有专业材料 | 用真实材料确定语域、内容和场景任务 |
| 用户目标改变 | 同时检查计划与教材是否仍相关 |

教材详细方法见[教材检索与构建](material-and-curriculum.md)。

## 4. 课程计划应写什么

计划是大模型后续备课的路线图，至少让它知道：

- 用户最终目标和当前优先级；
- 当前起点中已知与未知的部分；
- 阶段和章节怎样对应；
- 每个阶段的关键任务；
- 哪些基础能力需要跨章节反复练；
- 预计课堂、课外和日历时间；
- 首个阶段为什么这样安排；
- 什么课堂证据会让计划保持、调整或重做。

不要过早写数据库字段、枚举和状态机。计划先确保教学关系清楚。

## 5. 时间估算

分三层估计：

### 全课程

只给量级和假设。用户目标通常比完整 CEFR 升级更窄，不能拿等级小时数直接承诺。参考资料显示从零到 A1、A2 等级需要大量 guided learning hours，但个体、目标范围和课外投入差异很大。[Cambridge English](https://support.cambridgeenglish.org/hc/en-gb/articles/202838506-Guided-learning-hours)

### 阶段

根据章节数、任务复杂度、复现次数和课频估算范围。

### 单章

用一节代表性教案估算完成学习闭环需要几课，再在前两三课后修订。计划中写清：

```text
课堂时间
课外输入/复习时间
按当前课频的日历周期
估算前提
下一次修订点
```

## 6. 调整计划

正常的小调整包括：

- 章节前后移动；
- 某章多上一课或减少内容；
- 补一段听力、更多任务或复习；
- 因用户近期事件临时提高优先级；
- 替换不合适的材料。

只有下列情况才需要重做大计划：

- 用户目标实质变化；
- 起点判断被连续课堂推翻；
- 多个章节长期无法服务真实任务；
- 可用时间和期限发生重大变化。

调整时保留已经学过的内容和证据，不把旧计划抹掉。

## 7. 完成检查

一份计划应能回答：

1. 这是用户的目标，还是模型替他发明的目标？
2. 现实中究竟要完成哪些沟通任务？
3. 为什么按这个顺序学？
4. 教材从哪里来，各章节怎样对应计划？
5. 第一阶段现在能否开始？
6. 预计投入多少时间，依据是什么？
7. 下一节课可以从哪一章拆出教案？
8. 什么新证据会改变计划？

首次建课时，“计划写完”不等于“工作完成”。还必须：

- 保存与计划对应的 learner curriculum；
- 从首章编译并校验 `L001`；
- 把 S1→S4 的 `setup_schedule` 交接落库；
- 让宿主创建 T-30、T0、T14 定时任务，并登记真实 task ID；
- 向用户展示目标、教材目录、首阶段计划、首课内容和排程结果。

任一项缺失，都要继续执行或明确报告阻塞项，不能只说“课程已经规划好了”。

## 8. 工程落点

脚本保存课程计划的版本、目标、阶段、教材关联和修改依据；本文件决定这些内容为什么这样设计。`ADJUST / REPLAN` 发生时保留旧版本和已学证据，不覆盖历史。

## 脚本与交接

模型完成目标澄清和计划判断后，通过 `scripts/head_teacher.py save-document --kind course_plan` 保存计划。计划改版必须保留旧版本和修改原因；需要交给小菜或小King时，再写正式 handoff。
