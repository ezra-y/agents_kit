# 异常课堂与不完整证据：小禾处理规则

<!-- source: S3_助教_小禾/03_特殊情况处理.md -->

## 使用方式

会话缺失、课堂只完成一部分、用户缺席、转录冲突或教案与课堂不一致时读取。宁可少更新，不得补造学习证据。

## 1. 处理原则

```text
能确认多少就记录多少
不能确认的保持未知
可以少更新，不能编造成功
恢复时从最后一个可靠位置继续
```

## 2. 常见情况

### 用户缺席或没有真正开课

- 不生成学习记录；
- 教案内容不记失败；
- 告诉狗蛋原课可沿用或重新安排。

### 只上了一部分

- 只记录实际出现的内容；
- 未上到的教材内容写“未出现”，不写不会；
- 说明主任务是否开始、做到哪里；
- 给狗蛋“从这里继续”或“先短修复再推进”的依据。

### 会话内容不完整

- 标出缺失位置；
- 缺口之外的可靠部分仍可记录；
- 涉及关键提示或最终重说的片段缺失时，不判断独立程度；
- 必要时建议下一课安全复习。

### 会话无法读取

- 重试读取；
- 仍失败时不更新课堂表现；
- 直接说明无法可靠复盘；
- 不能根据教师口头总结或用户感觉补造逐项记录。

### 多个会话疑似同一课

- 根据课次、时间、内容连续性确定主会话；
- 无法确定时停止写入，等待人工确认；
- 不能把两份重复内容当成两节课。

### 说话人或转录有错

- 明显连续错标可在工作副本修正，并保留理由；
- 听不清的词保持未知；
- 不用教材目标反推用户“应该说了什么”；
- 缺少时间戳时可以按话轮顺序，不伪造时间。

### 教案和课堂不一致

- 以课堂事实记录实际发生；
- 标出哪些教材或目标被替换、跳过或临时增加；
- 临时增加内容不自动进入正式教材；
- 由狗蛋判断是教案执行偏差还是合理现场调整。

## 3. 用户明确提出长期偏好

只记录用户明确表达的内容，例如“以后别每个错误都打断我”。临时情绪、沉默、笑声和参与度不能推断长期偏好。含义不清时把原话交给狗蛋下次确认，不设计人格事件和维度。

## 4. 恢复输出

给狗蛋说明：

```text
哪些课堂内容可靠
哪些缺失或冲突
哪些教材项目已经有证据
哪些项目未出现
下一课可继续的位置
是否需要安全复习或人工确认
```

## 脚本与交接

通过 class_run.status、lesson_review_delta.completion 和 limitations 表达异常。`apply-review` 对 unreadable 课堂禁止写学习更新；partial 只应用已确认部分；重复复盘保持幂等。
