# 课堂复盘与学习记录：小禾执行指南

<!-- source: S3_助教_小禾/02_课堂内容提取与学习记录.md -->

## 使用方式

在 T-30 或人工补录时读取。以 Voice 会话为事实源，对照教案和教材逐项提取证据，再交给确定性记忆调度应用状态变化。

## 1. 读取顺序

```text
确认要复盘的课次
-> 取得该课唯一会话 ID
-> 读取完整课堂内容
-> 检查起止、说话人、顺序和缺失
-> 读取对应教案
-> 读取教案引用的教材章节
-> 按课堂任务和教材内容逐项提取
```

原始会话是事实来源。不要用教案“应该发生什么”反向补造课堂。

## 2. 先按课堂任务分段

不要按固定字数切 transcript。以这些变化分段：

- 进入新的教案环节；
- 主任务开始或结束；
- 教师提供新支援；
- 纠错后重新尝试；
- 任务条件改变；
- 课堂提前结束或转入临时问题。

每段要能说明教师要求什么、用户实际做了什么、得到了什么结果。

## 3. 对照什么提取

### 教材内容

逐项查看本课实际使用的：

- 句子与表达块；
- 词汇与搭配；
- 句型或表达模式；
- 互动策略；
- 听力或发音重点；
- 章节练习与主任务。

### 教学目标

查看：

- 单课目标；
- 章节目标；
- 当前阶段任务；
- 本课特别要求复习或重做的内容。

目标和教材内容都可以记录完成程度，但不能互相替代。用户说对几个句子，不一定完成了沟通任务；完成任务，也可能仍有语言问题。

## 4. 一次学习证据怎么看

对每个值得记录的尝试，回看：

```text
用户原本要表达什么
-> 用户实际说了什么
-> 此前教师给了什么帮助
-> 是否完成意思或任务
-> 出错后怎样修复
-> 是否完整重说
-> 是否在新条件下再次使用
```

至少区分这些事实：

- 只听到教师示范；
- 用户跟读或模仿；
- 用户在提示下说出；
- 用户不看完整答案独立说出；
- 用户自己发现并修复；
- 教师给答案后重新说；
- 换场景后仍能使用；
- 后续课程再次独立使用；
- 本课没有出现。

先保存这些事实，再由工程层按既有学习状态与记忆算法转换；小禾不能凭整体印象直接打分。

## 5. 句子、词和表达怎样对齐

- 原句完全出现时直接对应；
- 自然变形、代词替换或同功能表达，可以对应并保留用户实际说法；
- 同一句涉及多个学习点时分别说明，不虚增尝试次数；
- 无法确认对应哪一项时保留为未匹配，不猜教材 ID；
- 用户自己产生的高价值表达，可作为教材候选交给狗蛋，不直接入库。

## 6. 工程落点

每个教材项目先保存观察事实，再由现有记忆调度算法计算 `grade / status_after / next_review_at`。会话不可读时不得产生项目更新。字段和示例见 `工程实现/01_共享对象与字段.md`。

## 脚本与交接

先调用 `scripts/teaching_assistant.py review-context` 取得 class_run 和教案；宿主按 voice_session_id 读取完整课堂；模型生成 lesson_review_delta 草稿后调用 `apply-review`。脚本校验、重算记忆时间、保存记录并生成 S3→S1 handoff。
