# 定时任务：小菜执行指南

<!-- source: S4_学习分析师_小菜/02_定时任务说明.md -->

## 使用方式

首次设置课程节奏、用户修改时间或任务需要恢复时读取。Scheduled Task 负责“什么时候做”，四个 Skill 负责“怎么做”。

## 1. 目标

定时任务不是单纯提醒，而是把“复盘、备课、上课、阶段评估”按稳定节奏串起来。

小菜在首次课程计划完成后，根据用户确认的上课时间创建三类任务，并在用户修改学习时间或频率时同步调整。

---

## 2. T-30：上课前 30 分钟

这是每天最重要的后台任务。

顺序固定：

```text
检查上一节是否真的上过
→ 有待复盘课堂：调用小禾
→ 小禾根据 Voice 会话读取上一课并更新学习记录
→ 没有上一课、上一课未上或已经复盘：跳过
→ 调用狗蛋
→ 狗蛋读取刚刚更新后的学习状态、到期复习内容和当前课程计划
→ 准备今天教案
→ 教案确认可用后，向用户发送简短结果
```

用户看到的消息只需要说明：

```text
上节课最重要的进展 / 问题
今天课件已准备好
今天大概练什么
```

上一课复盘必须先于今天备课，因为上一课刚更新的句子状态和复习时间，可能直接决定今天应该练什么。

### 特殊情况

```text
第一节课：
没有上一课，直接备 L001。

昨天没上：
不伪造复盘，不因为日期过去就自动推进课程。

只上了一部分：
小禾记录真实完成部分；狗蛋决定继续、补强或重新组织今天的课。

上一节会话暂时不可读：
不猜学习结果。狗蛋优先沿用原计划或准备安全复习内容。
```

T-30 使用高质量文本模型完成复盘和备课。

---

## 3. T0：上课提醒

到用户约定的上课时间，检查今天教案是否已经准备好。

```text
教案 ready
→ 提醒用户打开任意 GPT Live
→ 告诉用户“小King已经等你上课”

教案未完成
→ 明确告诉用户备课没有成功
→ 不发送“课件已准备好”的假提醒
```

T0 不重新备课，也不做学习分析。

---

## 4. T14：周期评估

每 14 天触发一次小菜。

```text
检查本周期是否有足够的有效课堂证据
→ 不足：暂缓评估
→ 足够：进行周期评估
```

评估结果：

```text
KEEP
继续当前计划。

ADJUST
目标仍然合适，但教学节奏、难度、复习比例、支援或任务需要调整。
→ 同一次任务继续调用狗蛋做局部调整。

REPLAN
当前阶段目标已经完成、长期停滞、课程路线明显不匹配，或用户目标发生重要变化。
→ 同一次任务继续调用狗蛋重新制定阶段计划。

DEFER
证据不足，暂时不做教学路线判断。
```

周期评估的具体方法见 `03_周期评估与计划调整.md`。

---

## 5. 用户改变学习安排

用户修改：

```text
上课时间
上课日期
学习频率
阶段性暂停
```

由小菜更新对应 Scheduled Tasks。

已有任务应优先更新，不重复创建一套新的相同任务。

平台任务是否真正创建或更新，以宿主返回结果为准；失败就明确报告，不假装成功。

---

## 6. 设计原则

```text
Skill 定义“怎么做”；
Scheduled Task 定义“什么时候做”。

任务只负责编排角色，不复制角色 Skill 中的大段方法。

先让流程稳定，再自动化；
定时任务第一次创建后，应检查前几次真实运行结果。
```

平台能力和调用方式以最新 OpenAI Scheduled Tasks 官方文档为准。

## 7. 工程落点

`schedule_service` 创建、更新并核验 T-30、T0、T14，保存宿主返回的真实 task ID。任务 Prompt 只负责编排角色顺序，不复制四个 Skill 的方法内容。

## 脚本与交接

使用 `scripts/learning_analyst.py task-spec --kind t30|t0|t14` 读取任务模板；宿主真实创建或更新任务后，再调用 `register-task` 保存 task ID。不得用本地占位 ID 冒充已创建。
